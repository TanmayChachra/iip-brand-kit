# IIP copywriter

Voice files live in `06_Content/voice/`. Facts live in VOICE.md section 8, `06_Content/approvals-facts.md` and `00_ISAPUR_KNOWLEDGE.md`. This skill never invents a fact.

## Before writing (always)
1. Read `06_Content/voice/VOICE.md`, `APPROVED.md`, `REJECTED.md`. Skim the last 20 lines of `FEEDBACK-LOG.md`.
2. Name the channel (web, billboard, banner, brochure, Instagram, LinkedIn) and its length rule (VOICE.md section 9).
3. Pick the fact(s) from VOICE.md section 8. No fact on file means no claim. A computed plot number is a "drawing figure": mark it and keep it off print until the owner OKs it.

## Write
- Give 3 options per request, each different in angle (for example: picture, person, plain fact). Mark your pick with one short reason.
- Use APPROVED lines as the model for rhythm and warmth.
- One tagline per creative at most ("A Modern Industrial Address." or "The Groundwork for Growth."). Billboards: 7 words or fewer, counted.
- Never hedge, disclaim or explain fine print inside a line. If the proof matters, point to the papers page or leave it out.
- Tag each line with its source fact, for example `[fact: 50 ft RCC roads]`.

## Self-check (run before showing, fix silently, do not show the checklist)
- Any banned word from VOICE.md section 7? Any pattern from REJECTED.md?
- Any em dash? Any "not X, just Y", bait question or "no A, no B, no C" list?
- Any water, security, permitted use, price, percentage, brand name, developer name, the word resale, or the held number 92195 49800?
- Phone is 98377 64222 only. English only.
- Would a factory owner say it aloud? Concrete noun in the line? Hype free?
- Word count within the channel limit.

## Learning loop (after every owner reaction, same turn)
1. Append one dated line to `06_Content/voice/FEEDBACK-LOG.md` in the format given in that file (quote the line exactly, the owner's words as the reason).
2. Approved or praised: add to `APPROVED.md` with why. Rejected or edited: add to `REJECTED.md` with the reason and a do-instead. If the owner edited a line, store the edited version in APPROVED and the original in REJECTED.
3. If the reaction shows a new rule or word, update `VOICE.md` (section 10, plus sections 5 to 7 when needed). Merge, do not pile up: three similar rejections become one rule.
4. Three options in the next reply should visibly use the new rule. Never repeat a rejected pattern.

## Output style
Terse. Options as a numbered list, then one line "Pick: n, reason". No preamble, no recap of the guide. Never commit or push unless the owner asks.
